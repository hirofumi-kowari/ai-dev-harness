# ハーネスによるAI駆動開発

[English](README.md)

既存の業務システムにAIを使うときの一つの形を、短い動画2本で説明します。**ルールは人が決め、実行はAIが行い、判定は機械が行い、受け入れは人が決める。** 題材は架空の社員予約管理システムで、顧客名・製品名・実際のコードは含みません。

ナレーションは日本語（合成音声）です。英語字幕は今後の予定です。

**まずは[AI駆動開発デモ動画](dev-loop-demo.ja.mp4)をご覧ください。** 設計・製造・テスト・修正が続く様子と、人が課題を判断して承認する流れを紹介します。構築方法を知りたい方は、続けて[ハーネス技術編](harness-explained.ja.mp4)へお進みください。

## 1. まず見る：AI駆動開発デモ動画（11分）

改修依頼1件を最初から最後まで追います。AIが仕様とガードレールを読み、設計案を出し、決められないことを課題として起票し、設計書を更新し、実装・ビルド・テスト生成・自動テスト・画面テストを行い、別のAIのレビューを受け、品質ゲートを通り、証拠を人に渡して受け入れを仰ぎます。最後の場面では、今回の経験が組織標準になって次の改修で使われる様子を示します。

## 用語

| 用語 | 意味 |
|---|---|
| 仕様 | 要件・設計書。何を作るか。案件ごとに人が決める |
| ガードレール | 規約・許可範囲・チェックリスト。案件をまたいで使う |
| 自動チェック | ツール実行前・編集後・終了時に機械が走らせる検査 |
| 品質ゲート | 終了時の検査。定めた完了条件を満たすまで「完了」にしない |
| ハーネス | 全体の仕組み。ルールは人、実行はAI、判定は機械、受け入れは人 |
